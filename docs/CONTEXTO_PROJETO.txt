-----------------------------------------------------------------------
A. OBJETIVO DO PROJETO
-----------------------------------------------------------------------
Programa de desktop para Windows (C++) que complementa o sistema
"Playlist". Na Etapa 1 o programa devia: persistir/validar o caminho do
Playlist.exe; editar o playlist.ini como Bloco de Notas preservando a
codificação; abrir o ConfigManager.exe; e listar (somente leitura) os
DBFId do folders.xml na guia "Códigos".

Na Etapa 2 o programa ganha INTER-FACE completa e LEITURA dos formatos
de programação do playlist.ini:
  1. A interface passa a ser JUCE (janela, menus, abas, ComboBox,
     editor/dialogs) — item 41 do prompt);
  2. Leitura e interpretação das seções do playlist.ini
     ([BLOCO COMERCIAL], [BLOCO MUSICAL], [RELOGIO COMERCIAL],
     [RELOGIO MUSICAL], [AFILIADAS]) com validação e edição assistida;
  3. Guias: "Editor" (bloco de notas textual), "Configuração"
     (cartões por escopo + afiliadas) e "Códigos" (folders.xml,
     somente leitura).
  4. Núcleo lógico permanece em C++ puro (std::wstring), testável sem
     interface: o módulo src/readconf implementa as regras de formato.

Informações que ainda não existem na especificação continuam marcadas
como A DEFINIR / NECESSITA DE ESPECIFICAÇÃO.

Na Etapa 3 o programa ganha INTERFACES SIMPLIFICADAS com leitura do
formato REAL dos arquivos de Relógio:
   1. Menu "Editar" com os atalhos visuais; o antigo menu "Editar"
      (textual) vira "Avançado";
   2. Editor VISUAL dos Relógios Musical/Comercial (etapa 3) —
      src/relogio (núcleo do modelo, teste sem UI) + src/app
      (RelogioEditor/RelogioEditorTab): cada horário em uma linha com
      chips de parâmetros, paleta "grudada no mouse", Início/Intervalo/
      Avulso, Copiar/Colar de parâmetros entre relógios;
   3. Tela provisória para "Blocos Musicais"/"Blocos Comerciais"
      (o editor visual fica para etapa futura — NECESSITA DE EXEMPLO
      REAL). [SUBSTITUÍDA na Etapa 4 — ver B.4]

Na Etapa 4 o programa ganha o EDITOR VISUAL DOS BLOCOS (Mapas Comerciais
e Grades Musicais), com o formato real verificado nos arquivos da
instalação oficial:
   1. src/blocos (núcleo, sem JUCE): blocos::BlockDocument interpreta o
      arquivo real — "HH:MM COD, COD, ... " — preservando o separador, a
      vírgula/espaço final e QUALQUER linha que não seja horário
      (comentários, seções) verbatim; e blocos::CodeCatalogue monta a
      Lista de Códigos a partir do folders.xml;
   2. Painel de CÓDIGOS com no máximo DUAS FILEIRAS por padrão,
      navegação (‹ ›) quando há mais códigos do que cabe, altura
      redimensionável pelo usuário (1 a 8 fileiras) e uma cor por código;
   3. Editor VISUAL de Mapas/Grades: cada horário em uma linha com chips
      de CÓDIGO coloridos, código "grudado no mouse" (clicar no código
      arma; o clique num horário adiciona; botão direito/ESC cancela),
      Início/Intervalo/Avulso, Aplicar código aos selecionados,
      Copiar/Colar de horários entre arquivos, botão "+" para criar um
      CÓDIGO DE SESSÃO e lixeira que só remove códigos de sessão;
   4. Correção do leitor do folders.xml: o arquivo real usa <Folder0>..
      <Folder15> (não <Folder>), tem um bloco <Shared> que NÃO é código,
      e o pareamento DBFId/Title por ordem do documento trocava os nomes.

C. METODOLOGIA E DECISÕES TÉCNICAS
-----------------------------------------------------------------------
C.1. Linguagem e bibliotecas
  - C++17.
  - UI com JUCE 8.0.15, obtido via FetchContent do GitHub
    (GIT_SHALLOW TRUE). Só o módulo juce_gui_basics é vinculado
    (depende de juce_core/events/graphics).
  - Núcleo (core/, playlist/, models/, readconf/) sem dependência de
    JUCE: toda a lógica usa std::wstring e std::filesystem.
  - CMake requer LANGUAGES C CXX (o JUCE compila alguns .c).
  - CRT estática (/MT) — exe único sem redistribuível VC.
  - Código-fonte em UTF-8; MSVC com /utf-8.

C.2. JUCE_ MODAL LOOPS
  - O JUCE 8.0.15 desativa janelas modais por padrão
    (JUCE_MODAL_LOOPS_PERMITTED=0). A área de trabalho usa o
    comportamento clássico; o target ProgMaster define
    JUCE_MODAL_LOOPS_PERMITTED=1 (ver CMakeLists.txt).
  - Com isso ficam disponíveis DialogWindow::showModalDialog e
    FileChooser::browseForFileToOpen; mensagens usam AlertWindow
    (showMessageBoxAsync / MessageBoxOptions + showAsync).

C.3. Namespaces e organização
  - Classes da UI (src/app/) no namespace `app`. Exceções globais:
    ProgMasterApplication (ponto de entrada do JUCE) e os serviços do
    núcleo (Settings, PlaylistLocator, documentos etc.).
  - PlaylistInstallation, PlaylistConfigController e MainWindow no
    namespace app.
  - JUCE: os callbacks têm nomes específicos — Component
    usa visibilityChanged() (NÃO visibleChanged); TextEditor não tem
    setSingleLine (single-line é o padrão); String não tem
    fromUTF16 (usar CharPointer_UTF16 — ver JuceHelpers.h);
    FontOptions não tem withTypefaceStyle (usar o ctor
    FontOptions(name, style, size) ou Font(name, style, size)).

C.4. Quirk do MSVC documentado
  - O MSVC (14.44) rejeita definições FORA DA CLASSE de classes
    aninhadas em certos contextos do nosso código (erro C2911). As
    classes auxiliares da guia Configuração (ScopeCard, AfiliadaRow,
    AfiliadasCard) portanto vivem, por decisão, no namespace app como
    classes amigas (friend) de ConfiguratorTab — ver seção D.

C.5. Convenções (mantidas da Etapa 1)
  - Núcleo não toca em APIs de interface; tradução na fronteira.
  - Erros em duas camadas: mensagem de usuário x mensagem técnica.
  - Conversões std::wstring <-> juce::String apenas em app/JuceHelpers.h.

E. EXPLICAÇÃO DAS PEÇAS-CHAVE (POR MÓDULO)
-----------------------------------------------------------------------
E.1. readconf\FormatRules
  - scopeDisplayName, optionsForFormat/displayName: o formato de cada
    escopo é a "linha ARQUIVO" esperada, gerada na ordem FORMATO antes
    de ARQUIVO (formato TXT1 em 1º lugar; ex.: [BLOCO COMERCIAL] ->
    mapas\Mapa.txt / Mapa%a.txt / Mapa%d / Mapa%d-%m-%Y / %d-%m-%Y.TXT
    (Planner); [BLOCO MUSICAL] -> grades\Grade.txt / Grade%a.txt /
    GRADES\%d-%m-%Y.TXT (Maker); [RELOGIO COMERCIAL] -> Mapas\Relogio.txt
    / Relogio%a.txt; [RELOGIO MUSICAL] -> GRADES\Relogio.txt /
    GRADES\Relogio%a.txt).
  - Formato = combinação de arquivo (token) e layout reconhecido;
    Unknown preserva o texto original ao salvar.

E.2. readconf\PlaylistIniDocument e ReadingConfiguration
  - PlaylistIniDocument: seções do playlist.ini em memória
    (nome, ordem, linhas "Chave=Valor"), capaz de re-serializar o
    arquivo preservando o que não foi alterado.
  - readScope(doc, escopo, pastaDeProgramacao) -> ScopeSnapshot:
    presente? opção reconhecida? arquivo lido (arquivoAsWritten),
    token match e lista de arquivos esperados (com exists) no disco.
  - A pasta de programação é a pasta do Playlist.exe (instalação real),
    NÃO a raiz do drive: se o exe está em C:\Playlist\pgm\Playlist.exe,
    os arquivos são procurados em C:\Playlist\pgm\Mapas e \Grades
    (aplicado em MainWindow::refreshFromLocator).
  - Tolerância a variações reais do arquivo: seções acentuadas
    ("[RELÓGIO COMERCIAL]" reconhecida como RELOGIO COMERCIAL) e
    valores entre aspas ("ARQUIVO=\"Mapas\Mapa.txt\"").
  - Validação de afiliadas: endereço prefixado por "=" quando
    convém, porta 1–65535, flags de desabilitado; erros traduzidos
    pelo controlador para mensagens de usuário.

E.3. app\PlaylistConfigController
  - ÚNICA fonte de verdade em memória do playlist.ini.
  - load() / save() (valida + serializa + grava na codificação
    original via PlaylistIni/TextFileIO); isDirty/markClean;
    applyOption(escopo, formato); addMissingConfiguration;
    addAfiliada/updateAfiliada/removeAfiliada (com NOME = a chave);
    removeScope(escopo); flushPendingToDisk() (grava sem validação,
    para o Bloco de Notas); scopes()/afiliadas() para a guia visual;
    currentText()/setTextFromEditor() (guia Editor).
  - Nunca grava parcialmente: se a validação falhar, nada é escrito
    e o erro técnico vai para o log.

K. PROBLEMAS CONHECIDOS / LIMITAÇÕES
-----------------------------------------------------------------------
K.1. Codificação: arquivo 100% ASCII é tratado como ANSI (CP-1252)
     para criar/gravar arquivos como o Playlist (correção 25/09).
     Conteúdo multibyte válido continua sendo UTF-8 (com ou sem BOM);
     a detecção de ASCII-puro x UTF-8 real é feita em TextFileIO.
K.2. Sem suíte automatizada de GUI (validação manual) — A DEFINIR.
K.3. Índice do callback de MessageBoxOptions (0/1/2 p/ Salvar/Descartar/
     Cancelar, 0-based): comportamento validado por leitura do código
     (MessageBoxOptions::withButton indexa os botões em ordem); revalidar
     com click real quando houver teste GUI.
K.4. classesScopeCard/AfiliadaRow/AfiliadasCard são amigas de
     ConfiguratorTab (não aninhadas) por quirk do MSVC (ver C.4).
K.5. JUCE 8.0.15 é baixado no primeiro configure (requer Git e rede).
K.6. Localização da pasta de programação (24/09/2026): os arquivos
     Mapas/Grades e Relógios ficam ao lado do Playlist.exe (ex.:
     C:\Playlist\pgm\Mapas). A leitura agora usa a pasta do exe (ver
     E.2/E.3); a base da instalação (raiz do drive) é usada apenas
     para derived classification. Validar em campo se houver
           instalações com layout divergente.
K.7. Acentos na INTERFACE (causa raiz da rodada atual):
      o `juce::String(const char*)` constrói strings via
      `CharPointer_ASCII` — um literal UTF-8 como "Configuração"
      era convertido byte a byte e aparecia como "ConfiguraÃ§Ã£o".
      O problema é de CODIFICAÇÃO, não de acentos do sistema:
      corrigido convertendo todos os literais acentuados ao
      usuário para WIDE (L"...") que passam por `CharPointer_UTF16`.
       Partes da UI já apareciam certas (editor, cartões) porque
       usam `jstr(std::wstring)`.
K.8. CÓDIGOS DE SESSÃO e CORES (Etapa 4) — A DEFINIR pelo cliente:
       - O botão "+" do painel de Códigos cria um código que só existe
         enquanto o programa estiver aberto: ele NÃO é gravado no
         folders.xml e some ao fechar. Consequência prática: se o usuário
         salvar um Mapa/Grade usando um código de sessão, o arquivo passa
         a citar um código que não existe mais na Lista de Códigos da
         instalação. O rodapé sinaliza "código de sessão" no tooltip, mas
         ainda NÃO há aviso ao salvar.
       - A COR de cada código é derivada do índice no catálogo, não é
         editável e não é persistida: reabrir o programa pode trocar as
         cores se a Lista de Códigos mudar. A paleta (12 cores) e o
         contraste preto-sobre-cor foram escolhidos nesta etapa.
       - Escrever no folders.xml e guardar as cores em config.txt estão
         FORA do escopo até o cliente decidir o formato.
K.9. FIDELIDADE DO TEXTO (Blocos/Mapas/Grades): o round-trip é exato
       para o formato real e para o exemplo do manual oficial, mas o
       separador ENTRE códigos é normalizado para ", " (o que o Playlist
       sempre gera). Arquivos escritos por terceiros com "VHAB,COMER"
       (sem espaço) voltam com ", ". O separador do HORÁRIO, a vírgula/
       espaço final, a ordem, os códigos repetidos e as linhas que não são
       horário são preservados exatamente.

       editor VISUAL: só são visíveis/editáveis no modo Texto. O editor
       visual não tenta interpretá-las (não inventa sintaxe).

       códigos (a Lista real tem dezenas) a navegação ‹ › é necessária —
